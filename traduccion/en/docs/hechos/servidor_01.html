Setting up a Puerto Bravo server

A server is a small program you leave running so several people can play together in the same city. It saves the characters, the gangs and the neighborhoods, and it decides what happens between players. It doesn't need a powerful machine, and it works just as well for two friends as for a hundred people or more.

Everything can be done with the keyboard and a screen reader: there is a panel with a window for Windows and, on any system, the server can be run through text.

You can move through this guide by headings. Each way of setting it up has its own section, with the steps one by one. You don't need to read all of it: pick your way in section 3 and go to it.

1. What you need

  • A computer that stays on while people play: your PC, an old laptop, a NAS, a Raspberry Pi or a rented server.
  • On Windows you don't need to install anything: the server comes with the game.
  • On Linux, Mac, NAS or Raspberry Pi you need Python 3.8 or later, which is almost always already installed. You don't need to install anything else: the server only uses what comes with Python. You don't need the game there.
  • For people outside your home to join: open a port on the router, or use a private network. It's explained in section 13.
  • It uses very little: with a few players you barely notice it in the processor or the memory.

2. What's in the servidor folder

Inside the game folder there is a folder called servidor. Everything for the server is there, and everything it saves goes there. Game updates don't touch your configuration or your data.

  • Panel del servidor.bat (Server panel): opens the panel window. It's the easiest option on Windows.
  • Servidor por consola.bat (Console server): starts the server in a text window.
  • Parar el servidor.bat (Stop the server): stops the running server in an orderly way.
  • Arrancar con Windows - activar.bat (Start with Windows - enable) and Arrancar con Windows - quitar.bat (Start with Windows - remove): to make it start by itself when you sign in.
  • documentacion_es.html and documentacion_en.html: this guide, in Spanish and in English.
  • servidor.conf.ejemplo: all the options, explained one by one.
  • otros_sistemas: what you copy to a Linux machine, a Mac, a NAS or a Raspberry Pi. It contains the server code, the scripts arrancar.sh, parar.sh, reiniciar.sh and estado.sh, the systemd service puertobravo.service, and the Docker files: Dockerfile, docker-compose.yml and entrada_docker.sh.

When you start the server for the first time, these will also appear:

  • servidor.conf: your configuration.
  • datos_servidor: the characters, the gangs, the certificate and, inside it, the copias folder with the backups.

The server programs for Windows are in the game folder, next to the game: PuertoBravoServidorPanel.exe, the panel, and PuertoBravoServidor.exe, the console. Both always work with the servidor folder, wherever you open them from.

3. Choosing how to set it up

  • You want to play with some friends from your Windows PC and you want it to be easy: the panel, section 4.
  • You prefer a text window, or you're going to leave it running unattended: the console, section 5, and starting it automatically, section 6.
  • You have a computer with Linux, or you rent a server: sections 7 and 8.
  • You have a Raspberry Pi: section 9.
  • You have a Mac: section 10.
  • You use Docker: section 11.
  • You have a Synology NAS: section 12.

The configuration and the data are the same in all of them: you can start on your PC and move the server to another machine later. Section 20 tells you how.

4. On your Windows PC, with the panel

Starting it for the first time

  1. Open the game folder, go into the servidor folder and open Panel del servidor.bat. You can also open PuertoBravoServidorPanel.exe directly, in the game folder.
  2. The panel window opens, with the focus on the server status, which will say it's stopped.
  3. If you want to change something before starting, press Control+P to open the settings. The minimum is to give your server a name, on the first tab. Press OK to save.
  4. Press F5 to start. The first time it takes a few seconds, because the server creates its certificate to encrypt the connection.
  5. When it's done, the panel says "Server running" and the port. If Windows asks whether you allow the program to communicate over the network, say yes: without that, nobody can join.
  6. The Status tab shows the address you have to give to anyone playing in your own home. The Copy the address button puts it on the clipboard.
  7. Join first yourself from the game: the first account that joins is the admin.

The tabs

You switch tabs with Control+Tab and Control+Shift+Tab.

  • Status: whether it's running, how many people are on, the port, the address for your friends, the encryption with its fingerprint, and the world it's working with. One thing per line. It updates by itself only when something changes, without moving the cursor from where you have it; F6 updates it right away.
  • Players: who is on, where, and with which version of the game. With the buttons, or with the Applications key on a player, you can send them a message, kick them, ban them or make them admin.
  • Accounts: every account that has ever joined. From here you can ban, pardon a ban, give or remove admin rights and delete an account, even if the person isn't on.
  • Invitations: the invitation codes, free and used. You create, copy and cancel them here.
  • Log: what the server says as it goes, with the newest at the end. Below it there is a field to type commands to it, the same ones as in the console.

Panel keys

  • F5: start the server. Shift+F5: stop it. Control+F5: restart it.
  • Control+P: settings. Control+Q: quit.
  • Control+N: announcement to all players. Control+M: message to the selected player. Control+E: kick the selected player.
  • Control+I: create an invitation. Control+D: change the message of the day. Control+O: type a command.
  • F6: update the status and the lists.
  • Control+S: save now. Control+B: backup now. Control+R: restore a backup. Control+G: save the log to a file.
  • F1: open this guide. Control+H: explains the control you're on.
  • Alt plus the underlined letter: go to a control on the tab or open a menu.
  • Applications key, or Shift+F10, in the player and account lists: actions on the selected item.

The settings

  • Control+P opens a dialog with one tab for each group of options. Control+H on any control tells you what it does, what values it accepts and whether it needs a restart.
  • OK saves and closes. Apply saves without closing. Cancel changes nothing.
  • Factory defaults resets the options on the tab you're on, or all of them, to how they come out of the box. Nothing is saved until you press OK or Apply.
  • Almost everything is applied with the server running. If you change something that needs a restart, like the port or the encryption, the panel tells you and offers to restart right then.
  • The configuration is saved in servidor.conf, a text file with each option explained, which you can also change with Notepad.

Stopping and closing

  • Shift+F5 stops the server: it warns the players, saves everything and disconnects them. If there are people on, it asks first.
  • If you close the panel with the server running, it asks and, if you say yes, it stops the server in an orderly way before closing.
  • The server only works while the panel is open. You can minimize it.
  • Control+F5 restarts it: players are told it's a restart, and their games wait and rejoin by themselves as soon as it starts again.
  • If you update the game with the panel open, the panel closes by itself, in an orderly way, and opens again when the update finishes, with the server running again if it was. It's in section 20.

5. On your Windows PC, from the console

  1. In the game's servidor folder, open Servidor por consola.bat.
  2. The first time, it writes servidor.conf with all the options explained, and starts with the default values.
  3. The window tells you what's happening: which port it's listening on, whether it encrypts, who joins and who leaves.
  4. You type commands to it in that same window. Type ayuda and press Enter to hear them all. They're in section 16.
  5. To change the configuration, open servidor.conf with Notepad, change what you want and save. Then type recargar in the console: it applies what can be changed without restarting and tells you what is waiting for the restart.
  6. To stop it, type apagar, press Control+C or close the window. In all three cases it warns the players and saves everything.

The panel and the console use the same configuration and the same data: you can use one on one day and the other on another day, but not both at once.

If you know how to use a command window, you can call the program directly from the game folder:

  • PuertoBravoServidor.exe --ejemplo: writes servidor.conf and exits.
  • PuertoBravoServidor.exe --comprobar: checks servidor.conf, tells you what isn't valid and exits.
  • PuertoBravoServidor.exe --opciones: lists all the options with their explanation.
  • PuertoBravoServidor.exe --parar: stops the running server in an orderly way.
  • PuertoBravoServidor.exe --actualizar: stops it, warning the players that it's restarting to update. Their games wait and rejoin by themselves when you start it again.
  • PuertoBravoServidor.exe --reiniciar: the same, saying it's for maintenance.
  • PuertoBravoServidor.exe --puerto=47821: any option can be given like this, without touching the file.

6. Starting it automatically with Windows

When you sign in

  1. In the servidor folder, open Arrancar con Windows - activar.bat. It leaves a shortcut in your user's Startup folder. You don't need administrator rights.
  2. From then on, every time you sign in, the server starts by itself, in a minimized window.
  3. To stop it without looking for that window, open Parar el servidor.bat.
  4. To stop it from starting by itself, open Arrancar con Windows - quitar.bat.

When the computer turns on, without anyone signing in

This is for people with a dedicated computer. You need an account with administrator rights.

  1. Open Windows Task Scheduler: press the Windows key, type Task Scheduler and press Enter.
  2. In the Action menu, choose Create Task.
  3. On the General tab, name it Puerto Bravo Server and check Run whether user is logged on or not.
  4. On the Triggers tab, press New and choose At startup.
  5. On the Actions tab, press New. In Program/script, put the full path of PuertoBravoServidor.exe, which is in the game folder. In Add arguments, type servidor.conf.
  6. On the Settings tab, uncheck Stop the task if it runs longer than, so it doesn't get cut off after three days.
  7. Press OK. Windows will ask for your account password so it can start the task without a session.

Started this way it has no window. To stop it in an orderly way use Parar el servidor.bat, and to run it, the commands from the game chat, which are in section 16. If you choose End in Task Scheduler, it's cut off abruptly: you lose no more than the last minute, but it's better to stop it in an orderly way.

7. On Linux or a rented server, with Python

  1. Check that you have Python 3.8 or later: type python3 --version.
  2. Copy the game's otros_sistemas folder to the machine, with any name you like, for example puertobravo inside your home folder. Any way of copying files works: a USB stick, scp, or a file transfer program.
  3. Go into that folder: cd puertobravo. The servidor folder, with the code, must be inside it.
  4. Write the example configuration: python3 -m servidor --ejemplo. It creates servidor.conf.
  5. Change it as you like with a text editor, for example nano servidor.conf. To check there are no errors: python3 -m servidor --comprobar.
  6. Start it: python3 -m servidor. It tells you which port it's listening on and whether it encrypts. You type commands to it in that same terminal; ayuda lists them all. You stop it with apagar or with Control+C.

Leaving it in the background

  • sh arrancar.sh: starts it in the background, if it's not already running. What it says as it goes is kept in servidor.log.
  • sh estado.sh: tells you whether it's running and shows the last thing it said.
  • sh parar.sh: stops it in an orderly way.
  • sh reiniciar.sh: warns the players with the countdown, stops it in an orderly way and starts it again. This is what you use after putting in the new server code: the games wait and rejoin by themselves.
  • To make it start when the machine turns on without systemd, add a line like @reboot sh /home/tu_usuario/puertobravo/arrancar.sh to your cron, with crontab -e.
  • Started this way it has no console. You run it from the game chat, with the commands in section 16.

The firewall

  • If the machine has a firewall, you have to let the server port through over TCP. With ufw: sudo ufw allow 47820/tcp. With firewalld: sudo firewall-cmd --permanent --add-port=47820/tcp and then sudo firewall-cmd --reload.
  • On a rented server there is usually also a firewall in the provider's control panel, sometimes called a security group: open port 47820 over TCP there too.
  • A rented server has a fixed public address: there's no router to configure. The address for your people is puertobravo://, the machine's address, a colon and the port.

8. On Linux, as a systemd service

This way it starts by itself with the system, restarts if it crashes and stops in an orderly way when the machine shuts down. You need to be able to use sudo.

  1. Copy the server folder to /opt/puertobravo: sudo cp -r puertobravo /opt/puertobravo. The servidor folder must end up inside it.
  2. Create an unprivileged user for it: sudo useradd --system --home /opt/puertobravo puertobravo.
  3. Give it the folder: sudo chown -R puertobravo: /opt/puertobravo.
  4. If there's no configuration yet, write it: cd /opt/puertobravo and sudo -u puertobravo python3 -m servidor --ejemplo. Change it with sudo -u puertobravo nano servidor.conf.
  5. Copy the service: sudo cp /opt/puertobravo/puertobravo.service /etc/systemd/system/.
  6. Enable it: sudo systemctl daemon-reload and then sudo systemctl enable --now puertobravo.
  • See how it's doing: systemctl status puertobravo.
  • Hear what it says as it goes: journalctl -u puertobravo -f. You exit with Control+C.
  • Stop it: sudo systemctl stop puertobravo. Start it: sudo systemctl start puertobravo. Restart it, for example after changing the port: sudo systemctl restart puertobravo.
  • If you use another folder or another user, change the WorkingDirectory and User lines in the service file.
  • As a service it has no console: you run it from the game chat.
  • Restarting it with a warning, for example after updating it: an admin types /reiniciar or /actualizar in the game chat, or on the machine, from the server folder, sudo -u puertobravo python3 -m servidor --actualizar. The server warns with its countdown, saves everything and exits with code 75; the service starts it again by itself after five seconds, and the games rejoin.

9. On a Raspberry Pi

  • Any model with Raspberry Pi OS works: it already comes with Python 3. For a few friends, the most modest model is more than enough.
  • The steps are the same as on Linux: sections 7 and 8. The most practical thing is to leave it as a systemd service, so it starts by itself when you turn it on.
  • To copy the otros_sistemas folder you can use a USB stick, or scp from your computer if you have SSH enabled on the Raspberry Pi.
  • On the slowest models, checking the identity of whoever joins takes a little over a second. It only happens when joining; while playing you don't notice it.
  • Give the Raspberry Pi a fixed address on your network from the router settings, in the address reservation or static DHCP section. That way the address you give your people doesn't change, and the port forwarding keeps pointing to it.
  • Use a good-quality memory card and leave automatic backups turned on: cards wear out.

10. On a Mac

  1. Open Terminal and type python3 --version. If the Mac offers to install the developer tools, accept: they include Python. You can also install Python from its official website.
  2. Copy the otros_sistemas folder to the Mac, for example to your home folder with the name puertobravo.
  3. In Terminal: cd ~/puertobravo, then python3 -m servidor --ejemplo and, once you've changed servidor.conf as you like, python3 -m servidor.
  4. The first time, the Mac asks whether you allow incoming connections to Python: say yes.
  5. To leave it in the background the same scripts work: sh arrancar.sh, sh estado.sh, sh parar.sh and sh reiniciar.sh.
  6. To stop the Mac from going to sleep while people are playing, look in System Settings, in the energy or battery section.

11. With Docker and docker compose

  1. Copy the otros_sistemas folder to the machine where you have Docker, with the name puertobravo. Inside it are Dockerfile, docker-compose.yml, entrada_docker.sh and the servidor folder.
  2. Go into that folder and type docker compose up -d --build. It builds the image and starts the server.
  3. The datos folder appears next to it. Inside are servidor.conf, which is written automatically the first time, and datos_servidor, with the characters and the backups. They're outside the container: they survive updates.
  4. To change the configuration, edit datos/servidor.conf and restart: docker compose restart.
  • Hear what it says: docker compose logs -f. You exit with Control+C, without stopping the server.
  • Stop it in an orderly way: docker compose down. It warns the players and saves everything.
  • Type commands to it: docker attach puertobravo, type the command and press Enter. To leave without stopping it, press Control+P and then Control+Q. The easiest way is to run it from the game chat.
  • Don't use the apagar command inside Docker to stop it: Docker would start it again. Use docker compose down.
  • To restart it with a warning, the reiniciar and actualizar commands do work, from the game chat or with docker attach: the server warns with its countdown, saves everything and exits, and Docker starts it again. The games wait and rejoin by themselves.
  • If you change the port in servidor.conf, also change both numbers on the ports line of docker-compose.yml.
  • With Docker, all connections may reach the server from the same internal address. That's why the conexiones_por_ip option must stay at 0.

12. On a Synology NAS

With Container Manager

Container Manager is Synology's Docker package. You install it from Package Center, and it creates a shared folder called docker.

  1. Open File Station, go into the docker shared folder and create a folder inside it called puertobravo.
  2. Upload the whole content of otros_sistemas to that folder: the servidor folder, Dockerfile, docker-compose.yml and entrada_docker.sh. The other files don't get in the way.
  3. Open Container Manager and go to the Project section.
  4. Press Create. For the project name put puertobravo. In Path, choose the docker/puertobravo folder.
  5. Container Manager sees that there's already a docker-compose.yml there and asks whether to use it: say yes.
  6. Continue with Next to the end, without enabling the web portal, and press Done. It builds the image and starts the server. The first time it takes a few minutes.
  7. The configuration ends up in docker/puertobravo/datos/servidor.conf. You can change it from File Station with the Text Editor package. Then, in Container Manager, Project, choose puertobravo and, in Action, Stop and then Start.
  8. What the server says is in Container Manager, Container, puertobravo, Log tab.
  • If you have the NAS firewall turned on, in Control Panel, Security, Firewall, add a rule that allows port 47820 over TCP.
  • Give the NAS a fixed address on your network, or reserve one for it in the router, so the port forwarding doesn't stop pointing to it.
  • To update the server: upload the new servidor folder on top of the old one and, in the project, choose Action, Build. The datos folder is not touched.
